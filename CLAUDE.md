# Правила работы с вёрсткой

## Стек
- **Yoast SEO** — seo оптимизация
- **Secure Custom Fields (SCF)** — кастомные поля

## Натяжка
По возможности сразу производить натяжку (подключать реальные данные из SCF) — не оставлять заглушки там, где данные уже доступны.

## Классы текста
При создании вёрстки использовать готовые классы текста — не задавать стили напрямую там, где уже есть подходящий класс.

## Цвета
Использовать только цвета из CSS-переменных в `assets/css/base.css` — не задавать hex/rgb напрямую.

## Порядок работы
1. Сначала максимально точно воссоздать структуру (HTML/разметку)
2. Только после этого заниматься точными стилями

## Принципы кода
- **DRY** — не дублировать код, выносить повторяющееся в переиспользуемые сущности
- **KISS** — держать решения максимально простыми, без лишнего усложнения
- **BEM** — наименование классов согласно методологии БЭМ (`block__element--modifier`)
- **Без jQuery** — не использовать jQuery, только нативный JavaScript
- **Разбивка PHP** — PHP-код разбивать на `inc`-файлы по смыслу
- **Локальное подключение** — если требуется что-то подключить, скачивать и подключать локально (не использовать CDN/внешние ссылки)
- **Планирование** — при любых изменениях кода сначала составляем план

## Описание контента
Всегда описываем человекопонятно внешний вид, структуру и поля разрабатываемого контента.

## Спорные моменты
Уточнять у пользователя, если есть спорные или непонятные моменты — не додумывать самостоятельно.

## Модель для просмотра файлов
Использовать только модель **haiku** для просмотра файлов.
